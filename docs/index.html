Quectel EC25-EUX · Raspberry Pi · Go

SMS off a cellular modem, into Telegram.

A small daemon that watches one or more LTE modems over AT, decodes the PDUs, reassembles multipart messages, and forwards each one to whoever is meant to read it — then frees the slot on the modem.

Signal chain

What happens to a message

Each step is where something can go wrong, so each step is where the daemon keeps state.

The modem stores it

An EC25 holds 255 messages. When that fills, it stops accepting new ones silently — no error, no queue, nothing in the log.

The daemon lists and decodes

AT+CMGL in PDU mode, decoded in Go: GSM 7-bit and UCS-2, sender, timestamp, and the user-data header that marks a segment.

Segments are reassembled

A long SMS arrives in pieces that can be minutes apart. They are stored and merged when complete, or forwarded partial once the assembly timeout passes.

Routed by the SIM it arrived on

The ICCID is resolved to a phone number, so a rule can say “anything to this line goes to that person” rather than naming a modem.

Delivered, and recorded

Delivery is tracked per channel in SQLite. A failed send is retried; a message already delivered is never sent twice.

The slot is freed

AT+CMGD runs only after every channel has a recorded success. The database keeps the message, so the modem never fills up and no history is lost.

Running unattended

It is supposed to survive the night

A gateway nobody is watching fails quietly. Most of the work here is about noticing.

Modems are supervised

A USB re-enumeration, a read timeout, a modem that stops answering: the watch loop is reopened with exponential backoff and retried indefinitely. One dead modem cannot take the other down with it.

Outages are reported

A modem that has not completed a poll for five minutes is announced once, and announced again when it recovers, with the length of the outage. A failed alert is retried rather than dropped.

Reconnects re-read storage

Messages that arrive while the port is down are only visible in a fresh listing, so every reconnect re-lists the modem instead of resuming blind.

One bad message stays contained

A segment the pipeline cannot handle is logged and skipped. It never aborts the batch, and it never stops the messages behind it from arriving.
